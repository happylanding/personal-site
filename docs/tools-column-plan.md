## 〇、背景与目标

网站现有栏目：行业洞察 / AI 学习 / 实用技巧 / 书籍专区 / 投资复盘（隐藏）+ 首页 / 关于 / 联系 / 收藏夹（隐藏）。

现在需要一个新的**工具区**，承载三类东西：

| 类型 | 说明 | 例子 |
|------|------|------|
| 🔗 在线工具（收藏引用） | 他人已做好的网页工具，拿来即用 | 各类转换器、正则测试、JSON 格式化…… |
| 🧪 自研小工具（在线 Demo） | 后期自己开发的网页小工具，可直接在浏览器里用 | 某个日常重复性工作的免安装小工具 |
| ⚙️ 脚本工具（本地 CLI） | 已制作完成的脚本，针对日常重复性工作 | 批量重命名、批量转换、自动化脚本（已攒了好几个，待后续补充） |

**核心目标**：把这些工具收纳成一处「效率军火库」，既能自己日常快速取用，也能公开分享给访客，成为个人站的实用资产之一。

## 二、放哪里？——位置与入口方案

### 方案 A：独立顶层栏目 `/tools/`（✅ 推荐）

- 新增顶层栏目，路由 `/tools/`（英文 `/en/tools/`），与 insights/ai/tips/books 平级。
- 导航栏「实用技巧」旁增加「工具」入口（桌面 + 移动端都加）。
- 首页新增一块「工具箱」入口卡片（与四宫格并列或作为第五条），让访客能发现它。
- **理由**：工具是「拿来用」的公共资产，适合公开一级入口；与「收藏夹（隐藏自用）」形成「公开武器库 vs 私人灵感库」的清晰分工。

### 方案 B：挂在「实用技巧 tips」栏目下

- 作为 tips 的一个子类，用标签 `#工具` 过滤。
- **缺点**：工具（尤其可交互 Demo）和「文章」形态差异大，混在列表里不突出，后续要加 iframe/复制命令等组件会受到文章页模板约束。不推荐。

### 方案 C：隐藏入口（仿收藏夹）

- 页脚小图标 + 快捷键直达，仅供站主自用。
- **缺点**：用户明确说「网站上放一些工具」，隐含公开分享意图；脚本工具若只想自用，可后续再细分「私有工具页」。不推荐作为唯一方案。

### 结论

采用 **方案 A 独立顶层栏目**，同时吸收 C 的优点：页脚保留一个低调的「工具」小图标 + 快捷键（如 `t` 直达），站主自己访问也方便。

## 三、内容模型：三类工具

每类工具定义统一的字段，方便页面自动渲染与后续扩展：

```
名称 / 一句话简介 / 分类(type) / 链接(url 或 内嵌路由) /
脚本命令(command，脚本类专属) / 仓库(repo，开源地址) /
状态(status: online|dev|beta) / 更新日期 / 标签 / 使用量(可选) / 是否置顶
```

| 字段 | 在线工具 🔗 | 自研小工具 🧪 | 脚本工具 ⚙️ |
|------|------------|--------------|-------------|
| 打开方式 | 外链新窗口 | 站内 iframe 试玩 / 外链 | 复制命令 / 下载 / 跳仓库 |
| 状态徽章 | 在线 · 收藏 | 试玩中 · 开发中 | 稳定 · 内测 · 待整理 |
| 亮点交互 | —— | 直接可玩 | 一键复制命令 |

## 四、页面结构与信息架构

```
/tools/ 工具箱
├── 页头：标题 + 一句话定位 + 统计（共 N 件工具 · 自研 M 件 · 脚本 K 件）
```

## 五、趣味性呈现创意（按优先级 P0→P2）

### 🟢 P0 基础（上线必须有）

1. **分类 Tab + 三色标识**
   三类工具用栏目配色体系区分：在线工具＝冰蓝 `#0E96E9`、自研小工具＝墨绿 `#16A34A`、脚本工具＝琥珀 `#B45309`（与现有 `SECTION_COLORS` 风格统一）。一屏看清「这是别人家的 / 我自己做的 / 我写的脚本」。

2. **状态徽章（让页面“活”起来）**
   每张卡片带状态点：`🟢 在线` / `🟡 试玩中` / `🔵 开发中` / `⚙️ 稳定`。扫一眼就知道哪个能直接用。这是行业里「工具页」标配，也是最好的信任信号。

3. **脚本工具「终端卡片 + 一键复制」**
   脚本工具不贴一大段代码，而是做成终端窗口样式，展示一行核心命令 + 说明，点按钮复制到剪贴板，出现 `✓ 已复制` 反馈。既好看又真正“拿来能用”——这是脚本工具区最具实用价值的交互。

4. **在线工具「新窗口打开 + 来源标识」**
   明确标注 `外部工具 · example.com`，避免访客以为是你自己做的；尊重原作者的开放共享，也是行业惯例。

### 🟡 P1 推荐（上线第二波）

5. **自研小工具「站内试玩」**
   自研网页工具直接 iframe 内嵌，点「在线试用」在卡片内展开一个小面板（或弹层）即可操作，不跳走。参考 Oil® 站「可玩 Demo」手法——「能摸到的工具」比截图强一百倍。

6. **随机工具「扭蛋机」彩蛋**
   页头放一个「🎲 随机推荐」按钮，点击从工具库里随机抽一件展示。适合访客无聊时探索你的武器库，也呼应了站点已有的「宠物彩蛋」基因。

7. **数字即社会证明**
   自研工具/脚本显示使用量（如「累计运行 328 次」「被收藏 12 次」）。参考收藏夹里 oiloil / 花叔站总结的「用数字代替形容词」。前期没有真实数据可先隐藏，等功能上线再补。

8. **快捷键直达 + 页脚小入口**
   仿收藏夹 `g s` 玩法，增加 `t` 快捷键直达 `/tools/`；页脚版权行加一个低调的扳手/工具箱小图标。站主自己平时想用工具也能秒达。

### 🔵 P2 锦上添花（后续迭代）

9. **搜索过滤 + 标签云**：工具多了以后，用站内 Spotlight 同款搜索过滤。
10. **宠物 Gali 联动**：在工具页，宠物气泡 30% 概率说「这个脚本我刚帮你跑过，稳的」「这把螺丝刀挺好使」，把效率工具和站点 IP 串起来。
11. **「工具带」收藏夹**：访客可把喜欢的工具加入自己的「工具带」（localStorage），跨页面保留，下次来还在。
12. **更新日志**：脚本/自研工具迭代时，在卡片底部显示 `v1.2 · 2026-08-08 更新`，营造“持续维护”的活人感。

## 六、技术实现方案（数据驱动）

**原则**：与现有内容体系一致，纯 Astro SSG + 原生 JS/CSS，不引框架。

### 数据源：二选一（推荐 A）

- **方案 A（推荐）**：新增 content collection `src/content/tools/`，每个工具一个 `.md` 文件，frontmatter 含全部字段。与 `articles/`、`sites/` 架构一致，天然支持：自动类型校验、后续独立详情页、双语 frontmatter。
  ```yaml
  # src/content/tools/xxx.md
  ---
  title: "JSON 格式化"
  titleEn: "JSON Formatter"
  type: "online"          # online | app | script
  url: "https://example.com"
  status: "online"        # online | dev | beta
  updated: 2026-08-08
  tags: ["开发", "转换"]
  featured: false
  ---
  ```
- **方案 B**：单文件 `src/data/tools.ts` 类型安全数组。更轻，适合纯列表展示；但后续要详情页/单篇管理时不如 collection 灵活。

### 页面与组件

| 组件 | 职责 |
|------|------|
| `src/pages/tools.astro` + `en/tools.astro` | 列表页（Tab + 搜索 + 卡片网格） |
| `ToolCard.astro` | 单张工具卡（按 type 渲染不同形态） |
| `ToolIcon.astro` | 工具图标（可复用 ColumnIcon 的线性风格） |
| `CopyCommand.astro` | 脚本命令一键复制（含剪贴板反馈） |
| `ToolPreview.astro` | 自研工具 iframe 试玩弹层 |
| `ToolGacha.astro` | 随机工具扭蛋彩蛋 |

### 路由与导航

- 新增 `tools` 到 `ALL_SECTIONS` / `SECTION_ORDER`（若进首页四宫格则扩展为五格或独立一块）
- 导航栏（Header.astro 桌面 + 移动端）加「工具」入口
- i18n 字典（`src/i18n/ui.ts`）补齐中英文
- sitemap 不需要过滤（公开栏目，正常收录）

## 七、落地路线（分 3 个阶段）

```
Phase 0（本次）  策划评审：本文档确认命名/位置/优先级后开工
Phase 1          数据模型 + 列表页 + 卡片渲染
                 └ 先收录 2-3 个常用在线工具占位，页面即可上线
Phase 2          自研小工具上线
                 └ 选 1 个最常用的日常重复性工作小工具，做成站内可玩 Demo
Phase 3          脚本工具仓库化
                 └ 整理现有脚本 → 建 GitHub 工具仓库 → 卡片接仓库链接 + 一键复制命令
```

> 阶段细节：
> - **Phase 1**：新增 `tools` collection + 页面 + 导航，构建通过即合入。可直接复用收藏夹的采集流程（`sites/` 模式），CodeBuddy 帮收录。
> - **Phase 2**：自研小工具建议先做「纯前端、无后端、体积小」的，放 `public/tools/<name>/` 或站内路由，iframe 直接引用，零运维成本。
> - **Phase 3**：脚本统一放到 GitHub 仓库（如 `happylanding/tools`），卡片展示 README + 核心命令，复制即用；下载走 GitHub release。
