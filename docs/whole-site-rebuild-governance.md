# Galvin 整站视觉与体验重构：专家协作章程

## 为什么停止“挑一点、改一点”

当前问题不再是某个字号、边框或留白的局部缺陷，而是页面构图、文字层级、组件语法和移动端行为没有由一套单一系统共同约束。继续逐点修改会令选择器、例外样式与信息优先级不断叠加，最终即使每一个局部都“修过”，整体仍然不协调。

本轮改造将把 Galvin 视作一个中文内容产品，而不是 AI SaaS 或模板化个人主页。任何后续页面变动必须先通过完整构图、令牌映射和跨视口审查，再进入实现。

## 专家能力组合

| 角色 | 已启用能力 | 唯一职责 | 不负责什么 |
| --- | --- | --- | --- |
| 视觉总监 | `frontend-design` | 定义每个页面的单一读者任务、视觉论点、排版个性和整站构图语法。 | 不以流行模板替代内容判断。 |
| UX 与内容架构师 | `ui-ux-pro-max` | 检索并验证触控、筛选、导航、文字密度、移动端与反馈模式。 | 不直接套用其默认 SaaS 配色或字体。 |
| 审美系统架构师 | `apply-aesthetic` | 先完成 Brief Inference，再将视觉方向映射到 Galvin 的语义令牌。 | 不复制外部品牌的组件或视觉资产。 |
| 可访问性与实现审查 | `web-design-guidelines` | 审查真实代码中的语义、焦点、控件、动效、排版与暗色主题细节。 | 不决定品牌方向。 |
| 视觉 QA 工程师 | `galvin-aesthetic-qa` 与 `design-qa` | 执行 1440px、834px、390px 截图、缩减动态、axe、对比与视觉回归门禁。 | 不在没有构图决策时通过局部 CSS 修补。 |
| 回归测试工程师 | `test-driven-development` | 为每项可观察行为先写失败测试，防止重构破坏阅读、筛选、搜索与导航。 | 不把测试当成审美判断的替代品。 |

## 已拒绝的方向

自动生成的通用“AI 产品”设计系统被明确拒绝。它将 Galvin 错配为聊天机器人/产品演示站，并引入浅色底、Inter、圆角卡片、紫青 SaaS 色板和产品演示布局；这些都与项目的深色中文编辑工作台、Noto Sans SC、内容优先与低噪层级相冲突。Galvin 继续以项目内 [DESIGN.md](../DESIGN.md) 为硬约束。

## 整体重构方法

第一步是冻结单页微调，建立全站视觉与体验基线：导航、首页、造物、叩问、行迹、藏页、书架、关于、页脚与搜索均以同一组三视口审视。第二步是把诊断转成单一设计系统，包括文字角色、阅读宽度、间距节奏、容器深度、交互状态和移动端断点。第三步只为三种页面原型定稿：入口页、内容目录页、内容详情页；其余页面从这些原型派生，而非各自发明样式。

在完成整站蓝图和关键页面静态构图后，先进行一次整体方向确认。确认后才以共享组件和令牌批量实施，不再要求用户在每个页面中寻找零碎问题。每轮交付都需通过跨视口截图、缩减动态、键盘与触控、axe、类型检查、构建和浏览器回归。

## 不可突破的约束

Galvin 保持“静默仪器室”：深蓝黑内容工作台、冷白中文阅读文本、电紫仅用于操作状态、荧青仅用于“正在发生”。避免卡片墙、装饰编号、英文眉标堆叠、假统计、渐变标题、WebGL 粒子、滚动劫持、全局自定义鼠标和小于 14px 的必要阅读信息。
