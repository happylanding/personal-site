# Galvin 设计技能与导航信息架构复盘

日期：2026-08-15
状态：**待 Galvin 确认；确认前不修改 Header、搜索或路由。**

## 1. 结论先行

`VoltAgent/awesome-design-md` 对本项目有帮助，但它**不是可导入的 Agent Skill**。它的价值在于提供一组可版本化的 `DESIGN.md` 参考：每份文档拆出视觉主题、令牌、字体、组件状态、布局与 Do/Don't；我们应从中选择并改写为 Galvin 自己的设计约束，而不是复制某个品牌的外观。[1]

本轮的最佳组合不是继续安装所有“设计”技能，而是采用**三项已启用能力 + 两项最小补充 + 一份项目内 `DESIGN.md`**。这个组合覆盖方向、证据、构图、实现、审查和视觉回归，且不会将多个相似技能的规则互相覆盖。

| 层级 | 工具/资源 | 状态 | 在 Galvin 的唯一职责 |
| --- | --- | --- | --- |
| 方向 | `frontend-design` | 已启用 | 在写代码前定义受众、单一视觉论点与页面的主任务，防止模板化 UI。 |
| 研究 | `ui-ux-pro-max` | 已启用 | 查询字体、色彩、空间、Astro、触达与动效的局部规则；不直接采用其不适合 Galvin 的 SaaS/文档默认样式。 |
| 参考 | `awesome-design-md` | 作为参考库，不导入 | 抽取一个深色编辑型参考的布局、深度、状态和禁用项，写入 Galvin 自有 `DESIGN.md`。 |
| 审美映射 | `apply-aesthetic` | **建议导入** | 强制先写 Brief Inference，再把风格选择映射为语义令牌，并通过对比检查。 |
| 质量门禁 | `design-qa` | **建议导入** | 为截图、深色模式、筛选状态、键盘与真实渲染对比建立视觉回归门禁。 |
| 代码审查 | `web-design-guidelines` | 已启用 | 对修改后的 UI 代码做实现级 UX/可访问性审查。 |

`apply-aesthetic` 和 `design-qa` 来自 `plugin87/ux-ui-agent-skills`，均为 MIT 许可的独立 `SKILL.md` 子目录；前者要求在生成前完成简报推断和令牌映射，后者覆盖令牌/硬编码检查、axe、真实渲染对比与跨视口视觉回归。[2]

以下候选不纳入本轮：Open Design 是完整桌面设计环境，过重；UI UX Agent Skill System 许可证清晰但生态较小且与当前技能重叠；UX/UI Principles 没有清晰许可证；旧 Superdesign IDE 扩展停止维护。详细核验见 [替代设计技能记录](./alternative-design-skills-evaluation.md)。

## 2. 为什么七项一级导航没有按之前的归并方案落地

用户的记忆准确。最清晰的早期内容架构并不是“七项平铺”：`qichuan-content-architecture-v2.md` 明确提出“**四条线，一扇现在窗口**”，把“现在/此刻”作为首页常驻状态而不是一级栏目；`qichuan-column-names-v5.md` 又将导航收敛为“此刻、造物、叩问、行迹、藏页、关于”，并把工具、资料、书和链接统一放入“藏页”。

后来出现了三个没有重新做 IA 决策的偏移。第一，品牌从栖川回到 Galvin 后，执行计划把七个名称作为“已锁定决定”写入总表；第二，用户确认“书架”作为独立栏目后，书架直接被新增为第七个一级入口，而没有重新评估它与藏页的关系；第三，现有 `GALVIN_NAVIGATION` 以一维数组直接渲染 Header、移动抽屉、首页入口与搜索分组，令“每种内容类型都有一个一级链接”在技术上成为默认实现。

| 历史原则 | 当前实现 | 产生的问题 |
| --- | --- | --- |
| 此刻是首页常驻窗口 | `此刻` 是 Header 的第一个同级链接，仍指向 `/` | Logo 与此刻重复占用全局导航空间。 |
| 藏页收纳工具、资料、书和链接 | 藏页与书架并列，工具又归造物 | 资源/阅读关系被拆散，访客无法形成“这是收藏与索引”的共同心智。 |
| 行迹承接生活与个人节奏 | 现行导航指向 `/about#journey`，没有独立行迹页 | 顶级入口没有独立目的地，层级名与路由能力不一致。 |
| 导航只表现稳定主线 | Header、移动抽屉与搜索均硬编码七组 | 一次功能性追加导致所有场景都被迫平铺。 |

这不是用户需求反复，而是**内容模型、路由和全局导航没有被拆开**：内容分类可以保留七类，主导航不必等于每一个内容分类。信息架构决定内容关系，导航只是帮助用户发现内容的多个界面组件之一。[3]

## 3. 推荐的新导航：四条主线 + 一个资源分组 + 一个站点工具项

建议把“此刻”回归为品牌首页的常驻状态，并将“书架”归入资源分组。桌面 Header 只保留四条主线和一个带二级项的资源入口；关于保留为低权重站点工具项。

### 3.1 桌面一级导航

| 层级 | 标签 | 目的地 | 说明 |
| --- | --- | --- | --- |
| 品牌/Home | `Galvin` | `/` | 首页天然承载“此刻”，不再同时显示单独的“此刻”。 |
| 一级 | `造物` | `/tools/` | 作品、工具、Case、模板和可下载资源。 |
| 一级 | `叩问` | `/archive/` | AI 学习、工作方法、判断与长短文章。 |
| 一级 | `行迹` | `/traces/` | 南京、咖啡、训练、阅读和轻量生活记录；需补独立页面而非继续指向关于页锚点。 |
| 一级 + 二级 | `藏页⌄` | 点击展开 | “网站与资源” `/sites/`；“书架” `/books/`。父项是清晰的资源分组，不能再用隐藏含义的图标代替文字。 |
| 工具项 | `关于` | `/about/` | 身份、公开边界与联系；视觉权重低于内容主线。 |

Header 显示的内容链接由 7 个降为 4 个直接入口 + 1 个可点击资源组 + 1 个低权重站点项。这样既不隐藏“书架”，也不让“书架”“藏页”两项在没有内容关系解释的情况下占据相同位置。

### 3.2 藏页二级菜单

菜单只允许一层，不使用 hover 唯一触发或级联菜单。桌面点击 `藏页` 后，打开靠近触发器的小面板，包含两张文字项和一个总入口；键盘可打开/关闭、Escape 返回触发器。移动端则在全高导航抽屉中直接显示分组标题和两条链接。

| 二级项 | 标签 | 一句话说明 | 路由 |
| --- | --- | --- | --- |
| 01 | 网站与资源 | 我保留下来的网页、工具与分析笔记。 | `/sites/` |
| 02 | 书架 | 正在读的书、阅读状态与合法外链。 | `/books/` |
| 总入口 | 全部藏页 | 在资源索引页查看全部收录。 | `/sites/` |

此模式符合“相邻相关内容使用局部导航”的原则，也避免在宽屏上把导航整体隐藏；二级菜单以显式箭头与点击方式展开，不依赖 hover。[4]

### 3.3 搜索与首页的同步变化

搜索索引保留七种**内容类别**，但将呈现分为五个**发现分组**：此刻、造物、叩问、行迹、藏页（合并网站与书架）、关于。首页不再展示“七个入口”卡片墙，而展示当前状态、四条主线与一条资源索引。这样不会丢失书架的可搜索性、统计或独立路由。

## 4. 视觉试点需要如何重定义

此前的试点范围是“首页 + 叩问归档”。在新 IA 下建议将范围调整为：

1. **导航信息架构与 Header/移动抽屉**，因为首页和叩问页都依赖它；
2. **首页**，把此刻改为首页状态并改写栏目入口；
3. **叩问归档**，验证连续目录、标签轨道与阅读路径；
4. **藏页二级菜单的静态/交互样例**，只实现导航面板与路由，不重做藏页内容页。

关于页、页脚、行迹内容页、书架和藏页主体暂不重做。这样试点可以验证视觉系统与新的发现结构，而不是再次被七个页面的视觉债务拖散。

## 5. 确认后顺序

确认后先导入 `apply-aesthetic` 与 `design-qa` 两个子技能；再由 `awesome-design-md` 提炼一份项目内 `DESIGN.md`；然后完成导航数据模型、Header/移动抽屉、搜索分组、首页、叩问归档的构图与实现。所有改动仍只进入 `revamp/galvin-v1`，不触碰 `main`。
