# 个人网站改造V1：后续操作指南

> **使用原则：** 五条轨道用于分类和验收，不表示同时启动五个任务。每一阶段只开一个主任务；只有当主任务确实需要独立调查、且不会同时修改同一批文件时，才增加一个协作任务。

## 0. 当前起点：先冻结已通过的整站基线

当前代码位于 `revamp/galvin-v1`。整站已经完成纯色深色画布与四种页面原型的重构，现有视觉宪法是 [`DESIGN.md`](../DESIGN.md)，项目治理基线是 [`project-v1-baseline.md`](project-v1-baseline.md)。后续任何任务都必须继承以下不变量：全站 `#10131d` 纯色深色画布、中文内容优先、无背景特效、造物/叩问/行迹/藏页/关于导航结构、移动端与桌面同等验收。

| 当前应做 | 当前不应做 |
| --- | --- |
| 用 Git 分支预览确认已完成的整站重构 | 再以“看起来不够高级”为由加入网格、曲线、渐变、粒子、厚阴影或卡片墙 |
| 将每次新需求写成一个有边界的任务 | 同时让多个任务修改 `global.css`、导航或同一页面 |
| 以真实内容缺口决定下一项建设 | 为尚未有真实内容的栏目先堆假统计、假案例或占位评价 |

## 1. 阶段一：建立可追溯的项目节奏

| 项目 | 内容 |
| --- | --- |
| 任务 | `Q-001：建立项目化变更日志与提交模板` |
| 主轨 | 质量与交付 |
| 目的 | 让后续每个任务可定位、可复验、可回退，不再依赖聊天记录回溯。 |
| 主要文件 | `docs/CHANGELOG.md`、`docs/project-v1-task-template.md`、`todo.md`、Git 提交约定。 |
| 主要动作 | 建立变更日志格式；把任务代号、关联页面、验收记录、提交号和预览链接写入交付记录；约定一项任务一个功能性提交。 |

### 阶段一验收

1. 新任务可以使用模板写出**目标、非目标、依赖、验收标准**。
2. 已完成的改动可以通过任务代号找到对应提交、受影响页面和核验方式。
3. `todo.md` 只保留当前可执行项，已完成项明确关闭。
4. 不改变任何读者界面；运行 `git diff --check` 与 `npm run quality`。

> **需要你确认：** 无。此阶段只建立治理资产，不改变产品方向。

## 2. 阶段二：完成真实内容与公开边界审计

| 项目 | 内容 |
| --- | --- |
| 任务 | `T-001：审计首发内容与公开边界` |
| 主轨 | 文本与内容 |
| 协作轨 | 架构（只在 schema 需要补字段时参与） |
| 目的 | 让现有视觉系统承载真实、可公开、可持续更新的内容，而不是继续改空页面。 |
| 覆盖栏目 | 造物、叩问、行迹、网站与资源、书架、关于。 |
| 主要文件 | `src/content/` 下 Markdown、`src/content.config.ts`、工具配置、书目与资源数据。 |

### 必须完成的内容

| 栏目 | 最低内容线 | 不可触碰的边界 |
| --- | --- | --- |
| 造物 | 每个工具有一句真实用途、运行环境、输入/输出、隐私说明和操作入口 | 不上传或暴露单位文件、未脱敏样本、虚构使用效果 |
| 叩问 | 每篇有真实问题、摘要、日期、标签和可读正文 | 不把 AI 草稿直接当成未经核验的经验事实 |
| 行迹 | 南京、训练、咖啡、阅读只保留你愿意公开的慢速记录 | 不写精确生活轨迹或不希望公开的个人信息 |
| 网站与资源 | 每条保留原链接、来源、真实拆解和更新日期 | 不复制他人受保护内容或伪造体验结论 |
| 书架 | 书目、阅读状态、个人笔记、合法外链 | 不提供未授权全文或下载文件 |
| 关于 | 仅保留 Galvin、职业范围、公开联系方式和公开边界 | 不公开真实中文名、单位、项目文件或敏感数据 |

### 阶段二验收

1. 每个首发栏目至少有可访问的真实内容或清楚的真实空状态。
2. 所有外链、下载链接和书目合法入口逐项可访问。
3. 内容集合通过 schema，构建无错误：`npm run check && npm run build`。
4. 你审核一份“可公开 / 需脱敏 / 暂不公开”清单。

> **需要你确认：** 内容清单、公开边界、每篇新增文章/工具的事实准确性。

## 3. 阶段三：收敛信息架构与技术债

| 项目 | 内容 |
| --- | --- |
| 任务 | `A-001：收敛中文优先的路由与文案边界` |
| 主轨 | 架构 |
| 协作轨 | 文本与内容、质量与交付 |
| 目的 | 明确哪些遗留中英文路由、组件与搜索索引继续维护，哪些应冻结或下线，避免“主站中文优先、代码和索引双体系”长期漂移。 |
| 主要文件 | `src/i18n/`、`src/pages/en/`、`src/lib/galvin-routing.ts`、`src/pages/search-index.json.ts`、`src/components/Header.astro`、内容 schema。 |

### 决策顺序

1. 先输出路由清单：中文主路由、遗留英文路由、只用于构建的兼容路由。
2. 明确每项状态：保留、重定向、冻结或下线。未确认前不删除任何内容。
3. 将导航、站内搜索、sitemap、canonical 和语言切换策略改为同一结论。
4. 清理无主组件与不再被页面引用的旧视觉实现。

### 阶段三验收

1. `造物、叩问、行迹、藏页、关于` 在桌面和手机导航、搜索索引与 sitemap 中一致。
2. 不存在指向空页面、过期栏目或错误语言版本的主导航链接。
3. `npm run check`、`npm test`、`npm run build` 全部通过。
4. 使用 Playwright 检查核心路由均返回可读页面，浏览器控制台无新增错误。

> **需要你确认：** 英文遗留路由究竟保留还是逐步关闭；这会影响搜索、外链和历史链接策略。

## 4. 阶段四：把高频读者动作做完整

此阶段按单个功能任务推进，而不是一次性把所有功能重写。

| 推荐顺序 | 任务 | 主轨 | 读者价值 | 主要验收 |
| --- | --- | --- | --- | --- |
| 4.1 | `F-001：资源与书架维护性工作流` | 功能 | 让你能用 Markdown 稳定新增资源报告、书目与阅读状态 | 新增一条资源/书目的步骤文档化；搜索、筛选、外链、空状态均可用 |
| 4.2 | `F-002：工具页输入、隐私与失败状态完善` | 功能 | 让工具说明与实际操作边界清晰，减少误用 | 每个工具有输入提示、隐私边界、成功/失败/空状态与移动端验证 |
| 4.3 | `F-003：阅读体验精修` | 功能 | 让长文阅读、章节跳转、阅读进度与返回路径稳定 | 键盘目录、移动章节选择、缩减动态、长目录和窄屏测试 |
| 4.4 | `F-004：第二阶段网址分析服务评估` | 功能 | 只做架构、隐私和成本评估，不在未确认前上线服务端能力 | 技术设计、数据流、失败路径、速率/成本边界和用户确认 |

### 每个功能任务的共同验收

1. 先写失败浏览器回归或单元测试，再实现。
2. 所有关键按钮和筛选器可键盘访问，移动端触控高度至少 44px。
3. 同时验证成功、空状态和失败路径；不能只验证“正常输入”。
4. 跑受影响测试加完整 `npm run quality`；对主页面做 axe 审计。
5. 以 1440px、834px、390px 截图确认功能没有破坏阅读层级。

> **需要你确认：** 新增任何外部服务、文件上传、收费功能、后台、登录、网址自动分析或新的公开数据源之前，先确认范围与隐私边界。

## 5. 阶段五：建立长期视觉回归，不再逐点打补丁

| 项目 | 内容 |
| --- | --- |
| 任务 | `V-001：建立组件级视觉回归基线` |
| 主轨 | 视觉 |
| 协作轨 | 质量与交付 |
| 目的 | 将已确认的纯色深色工作台、阅读层级和移动构图变成可检测的资产。 |
| 范围 | Header、Footer、首页主张、目录工具带、文章阅读页、资源行、书目条目、关于档案。 |

### 视觉任务的执行方法

1. 先阅读 `DESIGN.md` 与整站重构蓝图，不从截图局部颜色开始。
2. 先写“读者第一眼应该理解什么”的简报，再决定标题、留白、控件和动效。
3. 只使用语义 token；不要为一个页面新增孤立颜色、字号、圆角或动画曲线。
4. 在完成后一次性检查三个视口，而不是桌面通过后再补手机。
5. 若用户反馈“整体不好”，优先诊断页面原型、信息优先级与内容密度，而不是单独改一个间距或阴影。

### 阶段五验收

| 检查项 | 通过条件 |
| --- | --- |
| 画布 | 所有页面为 `#10131d` 纯色深色底；无网格、纹理、背景图、曲线、粒子或页面级渐变。 |
| 排版 | 核心正文与控件不小于约定最小尺度；中文短语不以逐字断行换取视觉冲击。 |
| 层级 | 页面标题、说明、首个真实内容与行动入口形成连续阅读路径；装饰不得压过内容。 |
| 响应式 | 1440px、834px、390px 无水平溢出、无隐藏主标签、无不可点按钮。 |
| 无障碍 | 焦点可见、对比度达标、缩减动态可用，axe 无基础违规。 |

> **需要你确认：** 只有涉及品牌方向、色彩体系、核心布局范式或新页面原型时确认。局部实现与组件内部优化由现有宪法约束。

## 6. 阶段六：发布前总验收与持续维护

| 项目 | 内容 |
| --- | --- |
| 任务 | `Q-002：发布候选版本验收` |
| 主轨 | 质量与交付 |
| 目的 | 在将分支合并到正式生产前，验证真实内容、体验、技术质量和公开边界。 |

### 发布候选清单

1. 所有首发栏目有真实内容或真实空状态，主导航和页脚链接无死链。
2. 内容、图书、资源与下载入口满足授权和公开边界。
3. 执行 `npm run quality`。
4. 执行全量浏览器回归：`npm run test:e2e`。
5. 对首页、造物、叩问、文章详情、资源、书架、关于执行 axe 审计。
6. 在 1440px、834px、390px 完成最终截图检查；必要时复查缩减动态。
7. Git 工作树干净；提交信息可追溯；`revamp/galvin-v1` 分支预览可访问。
8. 由你在 Cloudflare/Manus 发布界面进行正式发布；任何生产分支合并或发布前先获得你的明确确认。

## 7. 如何启动下一项工作

在“个人网站改造V1”项目中新建或继续一条任务时，可以直接使用下面的提示词。将方括号替换为实际任务即可。

```text
启动 [任务代号：任务名称]。

主轨：[视觉 / 架构 / 功能 / 文本与内容 / 质量与交付]
协作轨：[如无则写“无”]
读者或维护者问题：[一句话]
目标页面/文件：[路由、组件、内容集合]
非目标：[本次明确不做什么]
依赖：[DESIGN.md、相关蓝图、前序任务、公开边界]

请先输出任务简报与可观察验收标准；涉及系统级决策时先向我确认。实现必须遵循 TDD：先写失败回归，再完成最小实现。结束时按“验收标准 → 实际结果 → 核验方式 → 未完成项”交付，并推送至 revamp/galvin-v1，不触碰 main。
```

## 8. 推荐的第一条新任务

建议下一条启动：

```text
启动 T-001：审计首发内容与公开边界。

主轨：文本与内容
协作轨：架构（仅在需要补充内容 schema 字段时）
读者或维护者问题：视觉系统已经完成，但各栏目需要真实、可公开、可持续更新的内容基线。
目标页面/文件：src/content/、工具配置、书目和资源数据、关于页文本。
非目标：不新增后台、不引入外部服务、不重做已通过的整站视觉系统。
依赖：DESIGN.md、project-v1-baseline.md、既有公开边界。

请先建立“可公开 / 需脱敏 / 暂不公开”的内容审计表，再提出首发内容缺口和最小补齐方案。
```

阶段二完成后，再根据内容审计结果启动 `A-001` 或 `F-001`；不要在内容边界未清楚前直接扩展功能或大规模改视觉。
