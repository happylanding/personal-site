# Galvin 关于页与页脚视觉工程审查

日期：2026-08-15  
审查范围：`/about/` 与全局页脚，当前实现的 1440px、834px、390px 视觉基线。

## 发现的问题

当前页面功能和内容边界正确，但视觉比例没有收敛为一套稳定系统。

| 区域 | 当前问题 | 视觉工程判断 |
| --- | --- | --- |
| 首屏标题 | 约 94px 的桌面大标题占据近半首屏，正文与元数据被压缩成很轻的附属信息。 | 标题过度承担品牌表达，应降至 68–76px 的上限，让导语和身份字段成为可读的第二层。 |
| 微型标签 | `ABOUT / 07`、状态、区块编号、区块标签、页脚标签同时使用 10px 等宽字。 | 单独看有系统感，但全页累计后形成过多“仪表盘噪声”；保留导航/状态/区块三类即可，字级提高到 11–12px。 |
| 工作事项列表 | 标题、正文、编号、右箭头在每行中分散，横向空白过多。 | 读者的视线在左编号、居中内容、最右箭头之间往返；右箭头应更弱或移入 hover，主文本列需更集中。 |
| 个人节奏区 | 31px 的长段落与 15px 的列表并置，落差过大且段落分行过多。 | 降低段落至 23–25px，并把两栏比例收紧，使列表不是“漂浮在旁边的细字”。 |
| 全页节奏 | 1440px 下页面全高约 2956px，区块间 76–84px padding 与大标题叠加，导致内容密度偏稀。 | 将主区块垂直间距收敛到 56–64px；通过更明确的容器边界而非大面积空白建立呼吸。 |
| 页脚 | 结构比旧版权行更完整，但身份、栏目、联系三列分布较散，底部文字仍偏小。 | 页脚应更像一个紧凑收尾区：降低垂直高度、增大关键链接文字、减少过度分散的空白。 |

## 视觉工程基线

后续实现以以下尺度为约束，而不是继续为单个组件添加局部字号：

| 语义层级 | 桌面目标 | 移动端目标 | 使用范围 |
| --- | --- | --- | --- |
| Display | 68–76px / 1.08 | 42–48px / 1.12 | 页面唯一 h1 |
| Section title | 34–38px / 1.22 | 26–30px / 1.28 | 每个内容区 h2 |
| Lead / statement | 20–24px / 1.55 | 18–20px / 1.6 | 导语、个人陈述 |
| Card / list title | 18–21px / 1.38 | 17–19px / 1.42 | 事项标题、联系标题 |
| Body | 15–16px / 1.7 | 15–16px / 1.7 | 描述正文 |
| Utility | 11–12px / 1.4 | 11–12px / 1.4 | 标签、编号、元数据；不低于 11px |

下一步将把标题、区块头、列表、联系区和页脚作为一个连续排版系统重建，而不是单独缩小或放大某一处。

## 截图补充观察

桌面底部截图进一步显示，联系区、下一步导航与页脚之间的留白被三条横线和大面积黑色空间切成了三个弱关联区域；页脚内的栏目和联系文字又回落到过小字号。移动首屏中，标题虽然没有溢出，但占据约 60% 的首屏高度，导致导语和元数据很晚才进入读者的可见范围。重构将以“首屏内看见标题、导语和至少一个身份字段”为目标，并将联系区到页脚的收尾压缩为更连续的两段。

移动内容区中，事项标题与正文的对比基本成立，但每项之间的横线、编号、箭头和标签叠加后显得机械；个人陈述又从 16px 正文突然跃升到约 22px 多行粗体，制造了不必要的重量断层。后续会减少可见分隔线的数量，统一正文色阶，并让个人陈述作为 20px 左右的引语式文本，而非第二个大标题。

移动下半段中，个人节奏列表在功能上清晰，但与联系区之间额外的分隔线和大空白让页面显得被切碎。联系模块本身的邮箱卡与 X 按钮有效，但其后又出现“从内容开始”的单独分隔区，造成三个连续的结束动作。重构会将个人节奏、联系与下一步导航收进更紧凑的节奏：保留一个主分隔点，减少无信息的垂直空白。

移动页脚确认当前栏目、邮箱和版权均落在 10–11px 左右的工具字级，虽然不溢出，但和上方大标题形成过强反差。重构后，栏目与联系地址将提升到至少 13–14px 的可扫描文本；工具标签和版权才使用 11px 等宽字。

## 外部排版依据

USWDS 建议普通正文至少使用有效 16px，较小文字仅用于短说明；长文本行高至少 1.5，标题行高可在 1–1.35；网页可读行长通常在 45–90 个字符之间，标题应与其所引导的正文更接近。[1] 因此，本次不会仅缩小大标题，而会同步调整正文基准、标题层级、各区块的上下间距和页脚的最小可读字号。
