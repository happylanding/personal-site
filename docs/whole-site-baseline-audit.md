# Galvin 整站视觉与体验基线审计

审计范围包括首页、造物、叩问、行迹、网站与资源、书架、关于和文章详情页；每页均审视桌面首屏，首页、造物、叩问和文章详情同时审视 390px 手机首屏。

## 总体结论

当前站点不是“缺少几个更好的 CSS 数值”，而是同时运行了三种不兼容的界面语言：第一种是深色编辑型内容站；第二种是带计数、状态盒和提示框的 AI 工具产品；第三种是英文眉标、编号与网格质感构成的早期科技模板。它们分别出现在不同页面，甚至在同一首屏叠加。用户因此无法在短时间内建立稳定预期，页面之间也缺少可辨认的家族关系。

| 优先级 | 系统性问题 | 真实影响 | 重构处理 |
| --- | --- | --- | --- |
| P0 | 同一栏目英雄模板被复制到工具、书架、行迹等性质不同的页面 | 所有页面像“另一个产品仪表盘”，而非不同内容入口 | 建立入口页、目录页、阅读页、档案页四种页面原型 |
| P0 | 文章详情封面和正文区重复标题 | 桌面与手机首屏均无法进入正文 | 只保留一次文章主标题，封面改为轻量识别条或移至首屏之后 |
| P0 | 工具和书架将计数盒、边界提示、筛选放在真实内容之前 | 手机首屏看不到可用工具/第一条书目 | 真实条目前置；计数、边界、状态降为内联元数据或按需说明 |
| P1 | 网格背景、英文眉标、装饰编号和句号贯穿各页 | “科技感”成为高噪声装饰，中文内容失去主导地位 | 背景仅允许出现在首页一个视觉场；移除无信息价值的英文和编号 |
| P1 | 控件语言断裂 | 资源页亮白搜索框、蓝色胶囊与全站深色阅读环境冲突 | 建立暗色输入、文本式筛选和资源行组件 |
| P1 | 文字角色过多且必要信息使用微型样式 | 标签、状态、导航和说明难以扫读 | 固定为展示、章节、条目、正文、元数据、控件六级文字系统 |
| P1 | 手机页面复刻桌面层级 | 首屏被英雄、状态框、说明占满；标题中文短语断裂 | 为移动端单独定义首屏任务和内容进入点，而不是只缩小桌面 |

## 页面观察

### 首页

首页已具备最有价值的资产：主张、学习者身份、两个入口与“此刻”状态。但视觉曲线、网格背景、状态注脚和后续内容仍像独立模块，未形成一条有节奏的阅读路径。手机端则出现中文短语生硬断行，说明展示文字的宽度、字距与换行没有作为系统规则处理。

### 造物、书架与网站与资源

三者都应属于“可检索内容目录”，但目前各自使用不同的产品化构图。造物和书架重复计数盒、边界提示、巨型标题和大卡片；网站与资源又以亮白输入框和蓝色筛选胶囊显得像另一套应用。整站应改用共享的“目录页”原型：简短页面说明、一个内联工具带、连续内容条目，按内容类型只改变元数据和辅助动作。

### 叩问与文章详情

叩问最近的筛选修正已经减少了标签墙，但其页头仍偏高、筛选和数量仍有多个停顿。文章详情页更需要优先重写：封面中的标题与正文标题重复，手机和桌面均牺牲了真正开始阅读的时机。

### 行迹与关于

行迹的连续列表方向正确，但巨型标题、装饰编号和青色眉标仍沿用通用英雄模板。关于页则重复首页主张，混入英文系统标签。两页都需要从“栏目大标题”转向内容语义：行迹是时间/地点索引；关于是个人工作档案和公开边界。

## 影响整站的重构原则

1. **不再为每个栏目设计一个英雄页。** 只有首页可以使用展示级主张；其余页面由 32–40px 的章节标题与直接可访问内容开始。
2. **让内容比界面先到达。** 工具、文章、书目和资源中至少一项真实条目必须在手机首屏出现。
3. **一个视觉场，而非全站网格。** 深色底、细分隔线与冷白文字是基础；网格/曲线只作为首页的单一辨识场，不能变成所有页面背景。
4. **控件像编辑工具，不像营销按钮。** 筛选、搜索、进度、状态保持文字优先、层级清晰、暗色一致；不再使用高饱和胶囊或亮白输入框。
5. **中文为主要排版材料。** 删除无信息价值的英文眉标和编号，使用可控的标题宽度和文字尺度来避免生硬断词。

## 建议的实施顺序

先完成共享的布局/排版/控件令牌与四种页面原型；随后先重写首页、造物、文章详情三页，以验证入口、目录和阅读的完整闭环。叩问、书架、网站与资源、行迹、关于从对应原型派生。Header、搜索、页脚和移动抽屉最后统一接入，以避免全局组件在原型尚未稳定时反复调整。
