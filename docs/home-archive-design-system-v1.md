# Galvin 首页与叩问归档页：设计令牌与三视口构图 v1

日期：2026-08-15
状态：待用户确认；确认前不修改页面代码。

## 1. 生成依据与取舍

本方案使用已导入的 `ui-ux-pro-max` 检索了深色界面、中文排版、个人内容页与 Astro 技术栈规则。检索结果确认了深色高对比、`Noto Sans SC` 中文字体、低动效、可见焦点、44px 触达目标和无 JavaScript 降级的重要性；但其默认“文档站”结构和浅色配色不适用于 Galvin。因此本方案保留其可读性与可访问性约束，将视觉方向收敛为《视觉试点简报》定义的“静默仪器室”。

> 这不是一套通用 SaaS 设计系统。它只服务于一位 AI 初学者的中文内容空间：阅读、发现问题、进入一篇文章或工具。

## 2. 令牌层

### 2.1 色彩与表面

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--g-canvas` | `#080b12` | 页面主画布；避免 OLED 纯黑造成内容漂浮。 |
| `--g-surface` | `#0e1420` | 需要承载交互的单个面层，例如搜索/筛选上下文。 |
| `--g-surface-raised` | `#141d2e` | hover、打开的筛选或少量行动块；不用于每张内容卡。 |
| `--g-line` | `#243149` | 低噪分隔线与清单刻度。 |
| `--g-text` | `#f2f5fb` | 标题与核心交互文字。 |
| `--g-text-muted` | `#aeb9cd` | 正文辅助信息，仍保持可读对比。 |
| `--g-text-dim` | `#71809a` | 仅用于短标签、时间与版权。 |
| `--g-violet` | `#9f95ff` | 主互动、当前筛选和一条关键路径。 |
| `--g-cyan` | `#67e6d0` | “更新中”等真实状态，单页最多一处。 |
| `--g-focus` | `#c8c2ff` | 键盘焦点；2px 外描边，不用阴影替代。 |

**限制**：不使用页面大渐变、文字渐变、玻璃拟态或持续发光。紫色不承担普通正文和所有按钮的背景；荧青不用于装饰。

### 2.2 字体角色

| 角色 | 桌面 1440px | 平板 834px | 手机 390px | 用途 |
| --- | --- | --- | --- |
| `--type-display` | `clamp(52px, 5.5vw, 76px) / 1.08 / 600` | `52px / 1.12 / 600` | `43px / 1.14 / 600` | 每页唯一主张或页面标题。 |
| `--type-title` | `clamp(30px, 3vw, 42px) / 1.22 / 600` | `34px / 1.25 / 600` | `28px / 1.28 / 600` | 区块标题；不与 Display 并列出现。 |
| `--type-article` | `24px / 1.36 / 500` | `22px / 1.42 / 500` | `20px / 1.45 / 500` | 文章清单标题。 |
| `--type-lead` | `19px / 1.65 / 400` | `18px / 1.65 / 400` | `16px / 1.68 / 400` | 首页说明与归档导语。 |
| `--type-body` | `16px / 1.72 / 400` | `16px / 1.72 / 400` | `16px / 1.7 / 400` | 所有可连续阅读的文本。 |
| `--type-meta` | `13px / 1.5 / 500` | `13px / 1.5 / 500` | `13px / 1.5 / 500` | 标签、时间、邮箱、导航和辅助动作。 |
| `--type-utility` | `11px / 1.35 / 500` | `11px / 1.35 / 500` | `11px / 1.35 / 500` | 仅短英文状态、微型分组名、版权。 |

**字体**：`Noto Sans SC` 同时承担中文 Display、正文与内容标题；`IBM Plex Mono` 仅用于数字、状态、快捷键和不超过一行的工具文字。页面不得用等宽字体承载长中文阅读。

### 2.3 空间、边界与动效

| 范畴 | 令牌 | 应用 |
| --- | --- | --- |
| 基准 | `4px` | 所有尺寸均为 4 的倍数。 |
| 内容间距 | `8 / 12 / 16 / 24 / 32 / 48 / 72 / 112px` | 组件内使用至 32px；区块间使用 48–112px。 |
| 容器 | `min(100% - 48px, 1280px)` | 桌面；平板变为 `100% - 40px`，手机为 `100% - 32px`。 |
| 边界 | `1px solid var(--g-line)` | 只用于清单、筛选轨道、交互状态与页面章节；不围住每个内容块。 |
| 圆角 | `0 / 8 / 12px` | 轨道和行动按钮可用 8–12px；内容列表保持平直。 |
| 动效 | `160–220ms cubic-bezier(.2,.8,.2,1)` | 只允许 opacity、transform、border-color、color；减少动态效果下立即呈现终态。 |

## 3. 首页构图

### 3.1 1440px：主张占据工作台，内容沿轨道进入

```
┌──────────────────────────────────────────────────────────────────┐
│  Header: Galvin / 7 个栏目 / 搜索（低权重、细线）                 │
├──────────────────────────────────────────────────────────────────┤
│  此刻 / 更新中                         现在正在做                 │
│  把好奇心，                             Galvin V1                 │
│  做成一点有用的东西。                   内容有秩序，探索有轨迹。   │
│  AI 初学者 × 数字政府/数字经济…         ────────────               │
│  [阅读最近的叩问 →]  查看正在造的东西                              │
├──────────────────────────────────────────────────────────────────┤
│  入口轨道  此刻 — 造物 — 叩问 — 行迹 — 藏页 — 书架 — 关于         │
├──────────────────────────────────────────────────────────────────┤
│  最近叩问                                      查看全部             │
│  文章一：标题 + 1 行摘要 + 主题/日期                                  │
│  ─────────────────────────────────────────────────               │
│  文章二                                         →                  │
│  文章三                                         →                  │
└──────────────────────────────────────────────────────────────────┘
```

Hero 为 `7:5` 两栏。左侧只出现一个 Display；右侧“现在正在做”不再是独立卡片，而是一条在对齐基线上的注脚。入口轨道只为栏目导航服务，取消七张同权卡片。最新文章由一篇主条目和两篇紧凑条目构成，不使用大编号。

### 3.2 834px：两栏压缩为主次阅读顺序

Hero 改为 `8:4`：主张保持左侧大栏，当前项目保持右侧短注脚；入口轨道允许折行但每一项保持 44px 触达高度；最新文章保持一列，第一条只通过标题尺度加权，不增加卡片底色。

### 3.3 390px：先读完整主张，再出现一个行动入口

Hero 单列。顺序为状态、主张、说明、主入口、次入口、当前项目。当前项目以细线分隔而非独立容器；入口轨道改为横向可滚动的文本轨道；最新文章按全宽行排列，正文摘要最多两行。手机首屏不出现栏目卡片墙、统计数字或额外边框。

## 4. 叩问归档构图

### 4.1 1440px：问题目录，不是仪表板

```
┌──────────────────────────────────────────────────────────────────┐
│  叩问                                          12 篇 / 检索内容    │
│  把遇到的问题摊开，把暂时没有答案的事写下来。                      │
│  [全部]  AI 学习  工作观察  方法实践  阅读记录                      │
├──────────────────────────────────────────────────────────────────┤
│  2026.08.15    AI 学习                                               │
│  Easy-Vibe：从...                                  →                 │
│  一行摘要……  #AI #学习                                             │
├──────────────────────────────────────────────────────────────────┤
│  2026.08.10    工作观察                                               │
│  …                                                                     │
└──────────────────────────────────────────────────────────────────┘
```

归档顶部为一个 `10:2` 的标题/操作关系：文章数量与搜索并列，不另建统计卡；标签紧接导语，作为唯一筛选轨道。清单使用全宽横线和固定的日期栏，不使用围合卡、伪表格、巨大 `01` 或每篇的彩色标签堆叠。首篇只以更强标题与 2px 左刻度强调。

### 4.2 834px：固定逻辑、压缩元数据

标题、计数、搜索仍在同一开端，但计数变为紧凑文本。标签轨道可以横向滑动，不折叠为难以发现的菜单。日期和栏目保持在标题上方的同一行；文章摘要按可用宽度完整显示。

### 4.3 390px：筛选为阅读入口的一部分

标题、导语、搜索文字按钮、横向标签轨道、清单依次流动。每个条目为：日期/栏目（13px）→ 标题（20px）→ 最多两行摘要 → 标签。整行链接的最小高度为 128px；箭头只在焦点/悬停时移动，不能成为唯一可点击区域。筛选按钮 44px 高，在激活时以紫色底线和文字，而非高饱和胶囊表示状态。

## 5. 组件约束与实现门禁

| 组件 | 必须保留 | 必须改变 |
| --- | --- | --- |
| Header | 七栏目、搜索、键盘可达性。 | 降低数字/英文的视觉权重，避免和页面主张竞争。 |
| 首页 Hero | 主张、两条真实入口、当前项目。 | 移除大面板感、冗余编号和戏剧性状态仪表。 |
| 栏目导航 | 七个真实路由。 | 从卡片网格改为文本轨道。 |
| 最新文章 | 真实文章、文章路由、日期和标签。 | 从平权行项目改为清晰的主/次阅读层级。 |
| 叩问筛选 | `tablist`、`aria-selected`、计数更新、全站搜索入口。 | 从面板式控制条变为贴近标题的内容索引。 |
| 文章列表 | 真实文章、整条链接、标题/摘要/标签。 | 移除每项封闭卡片与无意义大序号，使用连续目录。 |

## 6. 审查门禁

在实现前，用户需确认本文件中的视觉方向和三视口构图。实现后依次执行：

1. `web-design-guidelines` 针对修改的 Astro/CSS 文件完成审查；
2. 现有 Playwright 与 axe 回归保持通过；
3. 以 1440px、834px、390px 截图验证主锚点、正文尺度、筛选和触达高度；
4. 无 JavaScript 时首页内容、归档文章链接与筛选初始态仍可阅读。
